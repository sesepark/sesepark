# 프로젝트 README 표준 형식

내 저장소들이 같은 순서로 읽히도록 정리한 형식입니다. 새 프로젝트를 시작할 때 이 문서를
복사해 채우면 됩니다.

읽는 사람은 대개 **처음 30초 안에 이 저장소를 계속 볼지 결정합니다.** 그래서 순서가
중요합니다. 무엇인지 → 무엇을 하는지 → 어떻게 만들었는지 → 무엇을 못 하는지 순으로 갑니다.
기능 나열은 누구나 쓸 수 있지만, **왜 그렇게 만들었는지는 만든 사람만 쓸 수 있습니다.**
그 부분(`설계에서 신경 쓴 부분`)이 이 형식의 핵심이고, 나머지는 그 절을 읽게 만들기 위한
받침대입니다.

---

## 절 구성

번호 순서대로 배치합니다. `*` 표시는 해당할 때만 씁니다.

| # | 절 | 내용 | 분량 |
|---|---|---|---|
| 1 | `# 제목 — 한 줄 정체성` | 이름 뒤에 무엇인지 한 줄 | 1줄 |
| 2 | 도입 | 무엇을 왜 만들었는지 | 2~4줄 |
| 3 | 영문 요약 | `>` 인용문으로 국제 독자용 요약 | 2~3줄 |
| 4 | `## 무엇을 하는가` | 기능의 지도. 표를 권장 | 표 4~8행 |
| 5* | `## 이 저장소에서 내가 한 일` | 팀 프로젝트·포크일 때 **필수** | 5~8줄 |
| 6 | `## 구성` | 디렉터리 트리 + 줄마다 한 줄 설명 | 코드블록 |
| 7 | **`## 설계에서 신경 쓴 부분`** | **문제 → 판단 → 근거**. 이 형식의 핵심 | 3~6항목 |
| 8 | `## 실행` 또는 `## 문서` | 재현 방법, 또는 문서 색인 | 짧게 |
| 9* | `## 관련 저장소` | 포크·상류·분리한 기여분 | 목록 |
| 10 | `## 한계와 주의` | 하드코딩·미포함 자산·재현 제약 | 3~5줄 |

## 규칙

### 기능이 아니라 판단을 쓴다

7번 절이 다른 저장소와 갈리는 지점입니다. 각 항목을 **무엇을 만들었다**가 아니라
**무엇이 문제였고 왜 그렇게 풀었다**로 씁니다. 판단에는 근거가 붙어야 합니다.

> **엔코더 오차 상쇄** — GELLO endpoint 추적은 리더의 절대 관절값을 FK에 넣지 않고,
> 팔로워 기준 관절에 리더 delta를 더한 "가상 관절"을 사용합니다. 절대값을 쓰면 시작 시점의
> 수 ° 엔코더 offset이 FK 비선형성을 타고 null-space 움직임에서 endpoint 오차로 새기 때문입니다.

"~를 구현했습니다"로 끝나면 아직 덜 쓴 것입니다. "~때문입니다"까지 가야 합니다.

### 숫자를 쓴다

검증 가능한 수치가 형용사보다 강합니다. 커밋 수, 코드 줄 수, 마이그레이션 개수, 실측 지연
시간, 상류 대비 변경량. `빠릅니다` 대신 `288초에서 30초로 줄었습니다`.

### 기여 범위를 먼저 밝힌다

팀 프로젝트나 포크라면 5번 절을 위쪽에 둡니다. **내가 한 것과 남이 한 것을 분명히 나눕니다.**
경계를 스스로 긋는 편이, 읽는 사람이 의심하게 두는 것보다 낫습니다.

### README는 착륙장이지 매뉴얼이 아니다

README에는 한 번 읽고 방향을 잡을 내용만 둡니다. 단계별 운용 절차, 트러블슈팅, 설정값
사전은 `docs/`로 내리고 8번 절에서 색인으로 겁니다. 아래는 README에 두지 않습니다.

- 내부 TODO 체크리스트와 회의 결과
- 장비 시리얼 번호, 개인 경로, 좌표값
- 팀 내부에서만 통하는 약어와 진행 상황 메모

### 한계를 숨기지 않는다

마지막 절에서 하드코딩된 값, 저장소에 넣지 않은 자산(데이터셋·체크포인트·비밀값), 재현
제약을 밝힙니다. 감점 요인처럼 보이지만 실제로는 반대입니다. 경계를 아는 사람이 쓴
문서라는 신호이고, 남이 헛되이 시도하다 실망하는 일을 막아 줍니다.

### 한국어를 기본으로, 영문 요약을 붙인다

본문은 한국어로 씁니다. 대신 3번 절에 2~3줄짜리 영문 요약을 넣어 국제 독자가 무엇인지
파악하고 넘어갈 수 있게 합니다. 전체를 이중 언어로 유지하면 반드시 한쪽이 낡습니다.

## 저장소 위생

README 밖에서 챙길 것들입니다.

- **설명(description)과 토픽을 채웁니다.** 목록에서 저장소를 보는 사람은 README까지
  들어오지 않습니다. 한 줄 설명이 사실상 첫인상입니다.
- **중복 저장소는 하나로 합치고 나머지는 보관(archive)합니다.** 보관한 쪽 README 맨 위에
  어디로 갔는지 세 줄로 남깁니다. 지우지 않는 이유는 기존 링크가 죽지 않게 하기 위해서입니다.
- **포크에는 무엇을 바꿨는지 배너를 답니다.** 포크는 상류 README를 그대로 보여 주기 때문에,
  맨 위에 변경 요약과 상세 문서 링크를 넣지 않으면 기여가 보이지 않습니다.
- **비밀값과 개인정보는 커밋하지 않습니다.** 메일 주소, 토큰, 기기별 경로는 설정 파일로
  분리하고 README에는 넣는 방법만 적습니다.
